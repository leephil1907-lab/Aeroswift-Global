# AeroSwift Global

Premium multi-page logistics website for package shipping, air freight, international cargo coordination, shipment tracking and flight enquiries.

## Architecture
- React 18 + Vite public website
- Separate admin application entry (admin.html), served only on the configured admin hostname
- Express API and secure HTTP-only session cookie
- PostgreSQL persistence for users, enquiries, support conversations, shipments, documents and audit events
- Resend email notifications (optional until verified sender credentials are configured)
- Karrio carrier API integration (requires a live Karrio instance and configured carrier credentials)
- Branded invoice and receipt exports in PDF and DOCX

## Local development
```bash
npm install
npm run dev
```
For backend development, configure PostgreSQL and variables from .env.example, then run npm run build and npm start.

## Render deployment
The repository includes render.yaml. It defines one Node.js Web Service for both frontends and the API, plus one PostgreSQL database in Frankfurt. The admin interface is a separate application entry and must be served on the configured ADMIN_HOST custom hostname. Requests for admin paths on the public hostname are rejected.

Proposed resources: Web Service Starter (512 MB RAM) at $7/month and PostgreSQL Basic 256 MB at $6/month. This is approximately $13/month in service compute, excluding the existing Pro workspace subscription, usage overages, taxes and external provider costs. Review the Render Blueprint plan before applying. No paid infrastructure should be provisioned without explicit approval.

Set these secret values in Render: ADMIN_EMAIL, ADMIN_PASSWORD (strong unique initial password), ADMIN_HOST (exact admin subdomain), optional Resend values (RESEND_API_KEY, AEROSWIFT_ENQUIRY_TO, AEROSWIFT_ENQUIRY_FROM), and Karrio values (KARRIO_API_URL, KARRIO_API_KEY). JWT_SECRET is generated by Render. Initial admin account is created once if the email does not exist; changing the environment password later does not overwrite an existing account password.

## Security
- Admin interface is served only for ADMIN_HOST (or an admin.* host); public host admin paths return 404.
- Admin APIs require a database-backed administrator role on every request.
- Passwords are hashed with bcrypt; sessions use signed HTTP-only same-site cookies.
- API requests are rate-limited and protected by Helmet security headers.
- Customer shipment and support endpoints scope data to the authenticated customer.
- Admin HTML is marked noindex/nofollow; this is not access control.

## Current service boundaries
- Flight services remain enquiries; no live flight inventory, ticketing or fare booking is represented.
- Tracking uses Karrio only when a live instance and carrier integrations are configured. No simulated events or GPS coordinates are generated.
- Enquiries are persisted before optional email notification.
- Support ticket conversations and admin replies are stored in PostgreSQL.
- Invoice and receipt records are persisted; downloadable PDF and DOCX versions are generated from saved records.

## API overview
- GET /api/health — application and database health
- POST /api/auth/register, POST /api/auth/login, POST /api/auth/logout, GET /api/auth/me
- POST /api/enquiries — persisted website enquiry (also aliased at /api/contact)
- /api/support/tickets — customer ticket creation and conversation access
- /api/admin/* — admin-only overview, enquiries, support, shipments and document management
- POST /api/track — live Karrio tracking proxy

## Production checklist
1. Apply the Render Blueprint only after reviewing its estimated cost.
2. Configure the real domain and admin hostname; keep the existing Vercel deployment online until Render is tested.
3. Configure verified Resend sender/recipient addresses.
4. Connect a real Karrio instance and authorized carrier accounts before advertising live carrier coverage.
5. Test customer registration, login, data isolation, ticket replies, admin access, document downloads and database backups.
6. Confirm official business details and service coverage before publishing them.
